# SpacemiT K1 / X60 structural service CostSheet

선택은 effective tune CPU `spacemit-x60`, exact VLEN=256이다.
Model `spacemit-k1-direct-v1`, profile `spacemit-k1-256`, revision
`k1-structural-service-v1`. [공통 규칙](rule.md)을 따른다.

## 문서 사실과 고정 가정

공식 자료는 docs-chip commit `b43b4f7190e540e2e4394fc58c86741de904e4e3`로 고정한다.
[Datasheet V7.1](https://github.com/spacemit-com/docs-chip/blob/b43b4f7190e540e2e4394fc58c86741de904e4e3/en/key_stone/k1/k1_docs/k1_ds.md)은
RVV1.0, VLEN 256/128-bit, x2 execution width를 기술한다.
[CPU manual §8.2.3](https://github.com/spacemit-com/docs-chip/blob/b43b4f7190e540e2e4394fc58c86741de904e4e3/en/key_stone/k1/k1_docs/k1_usermanual/8.CPU_System.md)은
Reserved다. 따라서 아래 알고리즘과 처리율은 vendor 보장이 아니다.
[RVV 1.0](https://docs.riscv.org/reference/isa/v20260120/unpriv/v-st-ext.html)의
operand geometry, reduction seed, gather 및 memory semantics를 따른다.

Integer/FP/memory service 폭을 모두 128 bits로 가정한다. 이는 LLVM X60의
SMX60DLEN 및 TuneDLenFactor2와 일관된 출발점이지 FU별 공식 폭의 증명이 아니다.
아래 모든 Rule의 demand/work=1이다. Scalar 기본값은 1이며 dual issue로 나누지 않는다.
명령 가격과 body 가격은 service의 합이다. 실제 cycle 예측, dependency/window/port
모델이 아니며 latency, cache/TLB miss, bank conflict, overlap, runtime VL/stride,
mask density, early exit를 포함하지 않는다. Setup, 주소 계산, configuration이 별도
명령이면 그 명령에서만 계산한다. 전역 calibration은 없다.

## 고정 규칙표

B=256×data LMUL/EMUL, C(x)=max(1,ceil(x/128)), N=B/SEW이며 memory는 EEW를 쓴다.
Fractional LMUL을 먼저 올리지 않는다. Rule ID는 `k1:assumed-structural-` 뒤의 이름이다.
모든 행의 출처는 위 ISA semantics와 이 문서의 명시적 nominal 가정이며 같은 revision을 쓴다.

| Rule ID / 적용 형태 | 작업 분해와 식 | 채택한 가정 |
|---|---|---|
| scalar: 지원 일반 scalar/branch/configuration | service 1 | operand 공급 포함 |
| simd: 일반 integer/FP/convert/compare/merge/broadcast, VV/VX/VI/VF | C(B) | pipelined 128-bit service, scalar 전달 포함; FMA fused; reciprocal estimate는 lookup |
| wide: widening/narrowing | C(2B) | 가장 넓은 data source/result 폭 사용 |
| extension: VSEXT/VZEXT VF2/4/8 | C(B) | B는 넓은 destination, 확장 배율 중복 없음 |
| scalar-transfer: VMV/VFMV insert/extract | 1 | 단일 element 전달 |
| whole-register: copy/load/store group g | C(256g)=2g | 전송 service; spill도 동일 |
| contiguous: unit-stride memory | C(B) | 정상 공급, 추가 setup 없음 |
| segment: unit-stride F fields | C(FB)+C(FB) | 전송 뒤 별도 128-bit interleave/deinterleave pass |
| strided: 일반 및 F-field strided | NF | 주소 생성과 element 전송을 결합한 service; block 비용 중복 없음 |
| indexed: ordered/unordered | C(N×IndexEEW)+N | index 공급 후 element별 주소/전송; ordered는 순서대로, 지연 할증 없음 |
| slide: up/down/slide1 | C(B) | block 경계 carry/삽입을 포함한 streaming shifter |
| uniform-gather: VX/VI | 1+C(B) | source element 선택 후 broadcast |
| gather: VV/EI16 | C(B)×C(N×max(SEW,IndexEEW)) | source와 destination/index block 쌍 순회, 각 쌍에서 선택/갱신; VV index=SEW, EI16=16 |
| compress / iota | 2N | element별 predicate/rank 처리 1 + 선택 data/결과 이동 1 |
| mask: mask-only logic/search/prefix/popcount | C(256)=2 | 명목 full mask, block 내부 연산과 carry 포함; 활성 mask 길이 추정 없음 |
| simd: VID | C(B) | lane index 생성 포함 |
| ordered-reduction | N | seed에서 N회 직렬 누적, latency 곱 없음 |
| tree-reduction | 1+Σ C((N/2^j)×A), j=1..log2(N) | 균형 binary tree 뒤 seed 결합 1 |
| wide-ordered-reduction / wide-tree-reduction | 위 reduction 식, A=2SEW | N은 좁은 source 기준, 첫 누적에 확장 포함 |
| integer-iterative: scalar/vector div/rem | (W+2)×batches | radix-2 W단계 + 준비 1 + 마무리 1, 부호 처리는 준비/마무리에 포함 |
| fp-iterative: scalar/vector div/sqrt | (p+4)×batches | p=11/24/53, p+2 결과/guard/round 비트 단계 + 정규화 1 + rounding/packing 1; sticky는 잔여값 판정 |

일반 reduction A=SEW. Scalar batches=1, vector batches=ceil(N/(128/SEW))=C(B).
Sqrt는 단계마다 입력 두 비트를 소비하고 결과 한 비트를 생성하는 참조 recurrence다.
정상/reverse FP divide 및 signed/unsigned integer는 같은 참조 알고리즘이므로 같은 가격이다.
이는 K1 내부 divider 알고리즘이나 실제 II의 주장도, vendor upper bound도 아니다.
Mask/tail 보존과 predicate 처리는 기본 service에 포함한다. MIR Text를 파싱하지 않으며
TTI와 MIR에 같은 근사를 적용한다. 모든 element에 대한 명목 작업을 계산하고 runtime
값으로 compress/gather 등을 할인하지 않는다.

## Adapter와 검증 계약

TTI 예상 opcode sequence와 MIR 관측 opcode는 같은 sheet를 사용한다. Legalization과
materialization은 한 번 적용한다. Geometry가 없는 indexed TTI는 inherited 추정을 유지한다.
Scalar sqrt/fma의 scoped call 가격도 sheet를 사용하여 native call-cost 10에 잘리지 않는다.
Native scope, 다른 cost kind, CPU/VLEN과 다른 타깃 가격은 변경하지 않는다.
Unknown은 MIR에서 1+unknown, TTI에서 inherited fallback이다. 잘못된 geometry/overflow는
오류이며 spill 실패는 0이 아니다. Vector aggregate spill은 homogeneous group 검증 뒤
2Q, scalar는 Q다. {1,1,4}와 {2,2,2}는 방향별 모두12지만 collector의 group 구분은 유지한다.
정확한 유리수, scalar/tail 기준, 관측 stage와 fallback은 BACKEND_FEEDBACK 계약을 유지한다.

## 구현 검증

2026-11-01 기존 cache에서 지정 compiler/tools/test target을 `--parallel 2`로 빌드했다.
RISCVTests 51개, VectorizeTests 104개, pass-manager IRTests 7개가 통과했다.
LoopVectorize와 RVV stack-slot-coloring lit는 990개 통과, 377개 unsupported, 실패 0이다.
로그는 `.cache/k1-structural-service-v1/`에 있다. 이는 compiler 정합성 검증이며
hardware timing이나 성능 개선의 증거가 아니다.

## 과거 자료

이전 `llvm-x60-occupancy-v2`는 scheduler blob
`3d97bb05692912dc73c2ebbf03f121446f3331c1`의 ReleaseAtCycles를 전사한 모델이었다.
새 모델은 그 timing 배열을 사용하지 않으며 native scheduler는 수정하지 않는다.
성능 결과는 설계 입력이 아니다. 새 hardware timing이나 전체 dataset 실행을 하지 않는다.

Retained sweep은 325 kernels × 6 modes, 1,950 binaries, 5,850 successful samples다.
별도 313-input `dataset.sqlite` 비교와 다르다. 읽기 전용 재검사에서 모든 retained ELF의
SHA256이 DB와 일치하고 kernel별 source hash가 mode 사이에 같음을 확인했다.
동일 ELF에도 큰 sample 차이가 있으므로 whole-kernel elapsed time에서 instruction 가격을
역산하지 않는다. `.cache/k1-costsheet-review/`는 이전 compiler의 조사 자료이며 당시 staged
selection 진단은 `.cache/scalar-cost-unification/`에 분리한다. 과거 timing을 바뀐 코드에
할당하지 않는다. **새 K1 hardware timing 측정은 수행하지 않았으며 성능 향상을 주장하지 않는다.**
