# SpacemiT K1 / X60 native-relative CostSheet

적용: effective tune CPU `spacemit-x60`, exact VLEN=256.
TTI profile `spacemit-k1-256`, MIR model `spacemit-k1-direct-v1`,
revision `k1-native-relative-v1`. [공통 규칙](rule.md)을 따른다.

## TTI 계수

K1 TTI는 `spacemit-x60` subtarget의 `RISCVTTIImpl` 가격과 lowering sequence를
그대로 사용한다. Scalar/vector 산술, memory, reduction, intrinsic, call, cast와
spill hook에 별도 가격을 적용하지 않는다. 연산군별 native 대비 계수는 모두 1이다.
Legalization, materialization, promotion과 constant simplification도 native를 따른다.
Profile 이름과 CPU/VLEN 선택, whole-loop fallback은 유지한다.

MIR 가격 정책은 [Saturn](saturn.md)과 같으며 같은 내부 구현을 사용한다.
TTI는 CPU별 native tuning을 따르므로 K1과 Saturn의 모든 IR 가격이 같다는 뜻은 아니다.
다른 cost kind, native IC, probe 최적화와 final codegen도 native 정책을 따른다.

## MIR 가격과 계수

[Saturn의 MIR 가격표](saturn.md#mir-가격과-계수)를 동일하게 적용한다.
Vector fused FP는 widening 포함 `L=max(1,data LMUL)`, 일반 vector FP는 `2L`이다.
Scalar/vector spill·reload는 방향별 register units `Q`이며 whole-register body와
같은 단위다. Geometry 검증, unknown/error 처리와 비용 변환은 [공통 규칙](rule.md)을 따른다.

지원 명령 Rule은 `k1:native-relative:` 계열이며 fused FP는
`k1:native-relative-fma`다. Unknown Rule은 기존 opcode unknown 표식을 유지한다.
이전 `k1-structural-service-v1`의 128-bit service 식과 iterative 참조 알고리즘은
현재 가격에 사용하지 않는다. 과거 자료는 아래에 별도로 기록한다.

## 현재 구현 검증

2026-11-03 기존 Release/assertions/tests-enabled cache에서 지정 compiler/tools/test
대상을 `--parallel 2`로 빌드했다. RISCVTests 50개, VectorizeTests 104개,
pass-manager IRTests 7개가 통과했다. LoopVectorize와 RVV stack-slot-coloring lit는
990개 통과, 377개 unsupported, 실패 0이다. Native TTI 일치, Saturn MIR 가격 일치,
scalar/vector 정규화와 default-TTI 독립성을 검증했다.
로그는 `.cache/k1-native-relative-v1/`에 있다. Hardware timing이나 성능 측정은 아니다.

같은 날 `~/scripts/gen-cost-model-sweep.sh --target k1-linux`로
`rajaperf/stream-triad` 단일 case의 6개 모드 빌드를 검증했다. 현재 compiler hash,
모드별 플래그, IR의 `spacemit-x60` 및 exact VLEN256을 확인했다. 같은 raw IR과
기록된 opt 명령에 passive JSONL 보고만 추가한 별도 진단은 fallback 없이
`k1-native-relative-v1`의 post-frame MIR 수집을 확인했다.
6개 실행 이미지가 동일하여 generator 정책에 따라 ELF 출판은 생략됐다.
Sweep과 진단 자료는 위 cache의 `sweep-k1/`, `sweep-k1-diagnostic.jsonl`,
`sweep-check.json`에 있다. 전체 dataset 측정이나 실기기 실행은 하지 않았다.

## 과거 자료

`k1-structural-service-v1`의 2026-11-01 구현 검증 로그는
`.cache/k1-structural-service-v1/`에 보존한다. 이전 `llvm-x60-occupancy-v2`는
scheduler blob `3d97bb05692912dc73c2ebbf03f121446f3331c1`의 ReleaseAtCycles를 전사했다.
두 모델의 별도 가격식은 현재 사용하지 않으며 native scheduler는 변경하지 않는다.

Retained sweep은 325 kernels × 6 modes, 1,950 binaries, 5,850 successful samples로,
별도 313-input `dataset.sqlite` 비교와 다르다. 당시 ELF/source hash 재검사 기록은
`.cache/k1-costsheet-review/`, staged selection 진단은 `.cache/scalar-cost-unification/`에
있다. 이 자료는 이전 compiler의 결과다. 동일 ELF에도 sample 차이가 커서 실행 시간으로
명령 가격을 역산하지 않는다. 이번 복원에서는 hardware timing이나 전체 dataset을
재측정하지 않았으며 성능 향상을 주장하지 않는다.
